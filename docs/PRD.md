# 进销存系统 PRD v0.1

> 状态：v0.1 已确认（§7 决议 2026-11-03） | 更新：2026-11-03
> 本文档是所有开发工作的需求基准，变更须经确认后修改本文。

## 1. 产品定位

面向**单店 / 单仓库的小微商贸与零售商户**（小型批发、便利店、五金店、生鲜店）的云端进销存系统。

- 核心价值：开单快、库存准、老板一眼看懂赚了多少
- 设计原则：**简单优先**——90% 的日常操作 3 步内完成；高级功能默认关闭、按需开启
- 交付形态：云端 Web 应用（电脑浏览器为主，手机可查看）

## 2. 明确的范围边界

| 做什么 | 不做什么（当前版本） |
|---|---|
| 单店单仓进销存全流程 | 多仓多店连锁（表结构预留 warehouse_id，但界面不做多仓切换） |
| 采购/销售/退货/盘点/调拨/其他出入库/报价单/采购订单 | 生产加工、BOM、拼团营销 |
| 批次保质期（按商品可选） | 序列号管理（后续版本评估） |
| 多价位定价 | 会员积分、储值卡 |
| 简单应收应付（跟随单据生成） | 财务总账、发票管理 |

## 3. 用户角色

| 角色 | 权限范围（M4 实现，M0-M3 先单人使用） |
|---|---|
| 老板（管理员） | 全部功能 + 系统设置 + 报表 |
| 店员 | 开单、查库存、查商品；不能看成本/毛利（可配置） |

## 5. 单据类型与库存影响规则

| 单据 | 方向 | 库存影响 | 成本影响 |
|---|---|---|---|
| 采购入库 | 进 | 数量 + | 重算加权平均成本 / 记入批次 |
| 采购订单 | - | **不影响库存**（仅记录待入库） | - |
| 销售出库 | 出 | 数量 - | 结转销售成本 |
| 报价单 | - | 不影响库存 | - |
| 采购退货 | 出（对供应商） | 数量 - | 按该批/加权成本冲回 |
| 销售退货 | 进（对客户） | 数量 + | 按原销售成本退回 |
| 盘点单 | 调整 | 盘盈 + / 盘亏 -（`scope=location` 时就地调整该货架） | 盘盈按当前成本入账 |
| 调拨单 | 移库 | 单仓模式下仅留接口 | - |
| 其他入库 | 进 | 数量 + | 手工录入成本 |
| 其他出库 | 出 | 数量 - | 结转成本 |

**单据状态机**：`草稿 → 已确认（生效）→ 已作废`
- 是否需要"确认"步骤由系统设置控制，默认关闭（开单即生效，符合小店习惯）
- 已生效单据**不可修改，只能作废**；作废不物理删除，需回冲库存与成本
- 作废采购入库必须检查库存是否足够回冲（卖出去了则阻止或提示）

## 6. 核心业务规则（已确认）

### 6.1 成本核算
- 每个商品可单独选择成本方式：**移动加权平均** 或 **先进先出（FIFO）**，建商品时选定
- 加权平均：每次入库后 `新平均成本 = (库存金额 + 本次入库金额) / (库存数量 + 本次数量)`
- FIFO：出库按批次先进先出结转成本；**要求该商品必须启用批次**（系统强制校验）
- 已发生的出库成本不追溯重算（加权平均法从当前时点向前算）

### 6.2 批次与保质期
- 商品档案可勾选"启用批次"，开启后所有入库存单据必须录批次（可含生产日期/保质期天数→自动算到期日）
- 出库时：启用 FIFO 的商品自动按先进先出分配批次；其他商品可手工选批次或不选
- 临期预警阈值（天数）在系统设置中配置

### 6.3 库存控制
- 负库存开关在系统设置中，**默认禁止**；开启后允许先卖后补录，但销售成本仍按当时账面成本结转
- 商品可设安全库存下限，低于时在首页/报表提示

### 6.4 价格体系
- 每商品可定义多个价位（名称自定义：零售价 / 批发价 / 会员价…），开单时下拉选择
- 默认价位可设，开单自动带出；单行价格可手工改（是否允许改价可配置）

## 8. 非功能需求

- 并发目标：单店 ≤5 人同时使用，SQLite 足够；预留 PG 迁移（全程 GORM，禁用方言 SQL）
- 单号规则：业务层生成，格式 `类型前缀 + 日期 + 流水`（如 `CG20261103001` 采购 / `XS…` 销售）
- 金额一律整数分存储，界面元显示
- 所有删除为软删除；关键操作写审计日志
