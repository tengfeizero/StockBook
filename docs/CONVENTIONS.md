## 后端规范

- Go 1.22+，Web 框架 Gin，ORM GORM，驱动 `gorm.io/driver/sqlite`
- **禁止手写 SQLite 方言 SQL**（PRAGMA/AUTOINCREMENT/特有函数）；复杂查询用 GORM 表达
- 金额一律 `int`（分）；数量一律 `int64`（实际值×1000）；时间 `time.Time`（UTC 存储，前端转本地）
- 错误处理：service 返回 `*pkg.BizError{Code, Msg}`，api 层不写业务判断
- 单号生成：`pkg/docno`，事务内生成，格式 `前缀+yyyyMMdd+3位流水`，按天重排
- 所有写操作在 service 层开事务（`db.Transaction`）
- 每个业务规则变更须有对应单元测试（尤其成本计算）

## API 规范

- REST 风格，前缀 `/api/v1`
- 统一响应：`{ "code": 0, "msg": "ok", "data": {...} }`；code=0 成功，非 0 见错误码表
- 认证：`Authorization: Bearer <jwt>`
- 列表接口统一分页参数：`page`（1 起）、`page_size`（默认 20），返回 `{list, total}`
- 软删除字段 `deleted_at` 由 GORM 自动处理，查询无需显式过滤

### 错误码段（pkg/errcode）
| 段 | 含义 |
|---|---|
| 0 | 成功 |
| 1xxx | 通用（1001 参数错误 / 1002 未登录 / 1003 无权限 / 1004 资源不存在） |
| 2xxx | 库存（2001 库存不足 / 2002 批次缺失 / 2003 成本方式冲突 / 2004 库位库存不足 / 2005 库位容量不足） |
| 3xxx | 单据（3001 单据状态不允许该操作 / 3002 单号冲突 / 3003 作废回冲失败） |
| 4xxx | 档案（4001 编码重复 / 4002 商品已停用） |
| 5xxx | 授权/订阅（5001 授权过期；51xx 租户：5101 编码不存在 / 5102 已停用 / 5103 订阅到期 / 5104 编码被占用 / 5105 用户数超套餐 / 5106 套餐不存在） |

## 前端规范

- Vue3 `<script setup>` 组合式 API + TypeScript
- 组件库 Element Plus，布局：左侧菜单 + 顶部栏 + 内容区
- 金额展示统一走 `utils/money.ts`（分→元 `¥x.xx`），输入金额反向转换
- 表单校验用 Element Plus rules，必填/数值边界前端先拦一层（后端必须再校验）

## 秤码（电子秤标签）约定（v0.11）

- 码制不写死在代码里：品牌/型号差异全部通过 `scale_rules` 配置（位数、前缀、PLU 段、金额/重量段、小数位、校验方式），新增品牌只加数据
- 段位置一律 **1-based**（人读习惯），解析时统一转 0-based；金额小数位 2 表示"分"，重量小数位 3 表示"克"（即 kg 保留 3 位）
- 同时含金额与重量的码（18 位）**优先取重量**；纯金额码（13 位）数量 = 金额 ÷ 商品默认售价，允许开单时修改
- 校验：EAN 通用 mod10（自右向左权重 3/1 交替），13 位与 18 位同样适用；校验失败不得静默通过
- 秤码商品必须有唯一 `products.plu`；PLU 冲突返回 4006
- 解析失败必须回退普通条码搜索，不允许阻塞原有扫码开单流程

## 库位数量账约定（v0.12）

- 库存两层：`inventory`（商品×仓库，数量+成本）+ `location_inventories`（商品×仓库×库位，仅数量）。
  **成本永不按库位拆**——一个仓库一个均价，避免同一商品在不同货架出现不同成本
- `location_id = 0` 恒表示「未分配」，是合法值：存量升级、期初未指定库位、负库存差额都落在这里
- 硬约束：库位级**不允许负库存**（即便全局开了负库存开关）。指定库位不足 → 2004；
  全局允许负库存时的差额只记入「未分配」，用于暴露账实差异
- 出库不指定库位时的分配顺序：商品默认库位 → 其余库位按可用数量降序；可能跨库位拆成多条流水
- 移库单（transfer）只改库位分布：不改变仓库总量、不重算成本、不生成金额；
  流水成对写（源 out / 目标 in），作废时只回冲库位表
- 移库单作废若目标库位的货已出库 → 拒绝（3003），提示改用反向移库；不允许把库位扣成负数
- 期初建账、采购入库、销售退货入库、盘盈都直接写库位数量；任何改动 `inventory` 的代码路径必须同步库位

## 库位盘点与容量约定（v0.13）

- 盘点分两种口径，用 `documents.scope` 区分，语义不可混用：
  - 空（全仓）：items 的 quantity 是**商品全仓实盘数**，差额落在仓库总量上
  - `location`：items 的 quantity 是**该货位实盘数**，差额只调该货位（仓库总量随之同步）
- 按库位盘点**不得回填商品默认库位**——若某商品在该货架实际上没有，回填会把别的货架的账盘掉
- 同一 `(商品, 库位)` 只能出现一行（重复 → 1001），否则第二行会基于已被第一行改过的库位账面重复计差
- 盘点盘盈**不受库位容量限制**：容量是提醒手段，账实必须如实记录，不能因为"货位满了"拒绝记录盘盈
- 库位容量口径 = 该货位所有商品数量合计（与基本单位同量纲）；混装不同计量单位的货架应不设容量
- 超容处理默认「只提醒不阻断」，只有在系统设置 `location_block_overflow=true` 时才返回 2005 拦截入库/移入
- 占用率与状态由后端统一计算（`GET /locations`），前端不自算，避免各处口径漂移

## 盘点留痕与复盘约定（v0.15）

- 盘点单**必须记录全部已盘行**（含账实相符），不得只写差异行——否则「盘过哪些」无从证明，也无法复盘
- `book_qty` 只由后端在 confirm 时写入（取当时的库位/仓库账面），**不接受前端传入**；差异 = `quantity − book_qty`
- 确认时回填 `cost`：盘亏取 `ApplyOut` 返回的结转成本，盘盈取盘盈成本（用户填价或仓库均价）；无差异行 `cost=0`
- 复盘必须**基于当前账面**（初盘已调账后的账），不能拿初盘的 `book_qty` 当账面，否则会把初盘调整重复抹掉
- 已生效单据不可改数——复盘一律新开一张单并用 `ref_doc_id` 关联初盘，作废时才逐单回冲
- 差异金额 = `|diff| × cost`，只在前端按单据快照字段计算，不在前端重算成本
- 差异表默认只列差异行；打印与 CSV 导出必须是同一口径（同一 `viewRows` 来源）
- 老单据兼容：升级前的盘点单无 `book_qty`，整单账面全 0 时判定为历史单，差异列显示 — 并提示重盘，不得按 0 计算差异

## 库位容量计量约定（v0.17）

- 容量量纲由 `locations.capacity_mode` 决定（qty/volume/weight），**占用计算必须走统一的 SQL 表达式**（`usedExpr`/`usedExprOne`），不要在别处手写 SUM(quantity)——两种口径会算出两个「占用率」
- 内部量纲统一 ×1000：数量=基本单位×1000，体积=升×1000，重量=kg×1000；换算公式 `quantity × 单件维度 / 1000`
- 商品 volume/weight=0 视为「未登记」：占用按 0 计、超容拦截放行（无法核算），但必须通过 `unknown_skus` 让用户看见，不能静默吞掉
- 演示数据/初始化流程若会触发作业单据，必须先把 `location_block_overflow` 关掉——演示货架本就近满容，否则重置会被 2005 卡在半路，留下残缺数据

## 演示数据多行业模板约定（v0.18）

- **场景数据与生成流程分离**：行业差异（分类/商品/往来单位/货位/价位/抬头/单据量/批次号格式）全部写在 `service/demo_profiles.go` 的 `demoProfile` 里并登记到 `demoProfiles`；`service/demo.go` 只保留清库→建账→开单→收付款的通用流程。新增行业 = 加一份数据 + 注册，**不改流程代码**
- 每个模板必须固定随机种子（`Seed`），保证同一模板重置结果一致、演示效果可控
- 模板数据自检三条硬性恒等式，重置后必须为 0 不一致：`Σ库位 = 仓库总量`、`Σ批次结存 = 库存`、无负库存；货架状态至少覆盖「超出容量/接近满/正常」组合
- **演示批次商品一律用 FIFO 成本**：加权平均出库不扣批次结存，批次明细与临期展示会和库存对不上
- 最近 3 张销售单固定落在今天：首页看板「今日销售额」不能是 0，否则演示开场尴尬

## 多租户约定（v0.19）

- **ctx 必须贯穿**：所有 service 方法第一个参数是 `context.Context`，数据库句柄一律 `s.db(ctx)`（=`conn.WithContext(ctx)`），不允许绕过——绕过 ctx 的查询不会带租户条件，等于数据泄漏。编译器保证：漏传 ctx 会直接编译失败
- 隔离由 `gormx.TenantPlugin` 统一实现：Create 填充 tenant_id（批量插入逐元素）、Query/Update/Delete 追加 `tenant_id = ?`；ctx 无租户信息（启动/内部任务）时零干预
- 0 号租户 = 单机版，同样被隔离（单机账号看不到 SaaS 租户数据）；租户表/套餐表自身不带 tenant_id，属平台级
- 业务编码唯一性在**租户内**：8 张表的唯一索引已下沉为 (tenant_id, 编码)，由 `model.MigrateTenantSchema` 幂等迁移；新表不要再用全库唯一索引
- 系统设置存 `tenant_settings`（主键 tenant_id+key），读写必须走 `model.GetSetting/SetSetting`（内部按 `model.TenantOf(db)` 显式定位租户），不要直接 Where key 查
- 登录按 (tenant_id, username) 显式查询（登录阶段无租户上下文）；JWT 携带 tenant_id，`JWTAuth` 校验用户实际归属与令牌一致
- 到期/停用拦截在 `TenantGuard`：到期禁写不禁读（可导出+自助续费），停用读写全禁；/auth/* 与 /tenants/* 始终放行
- 多租户启用后**禁止**使用未登录的 `/demo/init`（会清空所有租户数据，已由 `HasTenants` 拦截）；租户内演示重置只影响本企业
- SaaS 租户豁免本地授权文件（LicenseGuard 对 tenant_id>0 放行），付费由订阅管理

## 盘点确认单次快照约定（v0.18 修复）

- 盘点确认的「账面快照 + 阈值判定 + 调账」整单**只做一次**（`confirmTx` 中已提出明细循环），绝不能放回逐行循环里——每行重拍快照会把已调账商品的账面改成调整后数量，差异全被抹平，差异表/审批/复盘全部失真

## 盘点差异审批约定（v0.16）

- 审批人 = 持有 `system` 权限的角色（主管/管理员），路由 `POST /docs/:id/review` 用 `RequirePerm("system")` 把关；前端按钮用 `auth.hasPerm(['system'])` 控制显隐，双端一致
- 超阈值盘点单 `status=review`、`review_status=pending`，**绝对不能调账**；库存与成本只在审批通过（或未触发审批的正常确认）时变动
- 审批通过调账**一律基于明细已存的 `book_qty` 快照**算差异，不得重读当前库存——待审批期间可能有出入库，重读会把别人的账盘掉；与普通确认共用 `applyStocktakeAdjust`
- 差异金额阈值在确认时按**仓库均价**估算（此时 cost 尚未回填），只是筛选口径，不是记账口径
- 账面为 0 的行不参与差异率（无基线），由金额阈值兜底；命中原因要写进单据备注，让主管不用打开明细就知道为什么被拦
- 驳回 = 作废（`void_reason` 带原因）+ `review_status=rejected`，必须整单作废，不做"部分通过"
- 待审批单允许开单人作废撤回：未调账，跳过 ReverseDoc；`Void` 要同时接受 `confirmed` 与 `review` 两种状态

## 打印页约定（v0.14）

- 打印页是**独立路由、不套侧边栏**（`/print/:id` A4、`/print/:id/ticket` 58mm），数据只走 `GET /docs/:id`，不新增后端接口
- 纸张尺寸写在 `@media print { @page { size: ... } }` 里：A4 = `A4 portrait`，小票 = `58mm auto`；屏幕预览用 mm 单位还原真实比例（`.paper { width: 58mm }`）
- 小票可打印区按 **48mm** 设计（58mm 纸两侧各约 4.5mm 撕边不可打），约 16 个汉字/行；明细用「品名独占一行 + 数量×单价……金额」两端对齐，不靠字符数补齐（中文在等宽字体下宽度不齐）
- 小票抬头/票尾一律取系统设置（`shop_name`/`shop_phone`/`shop_addr`/`ticket_footer`），**留空即不打印该行**，不要在页面里写死店名
- `status != confirmed`（草稿/作废）必须在票面加醒目「不作结算凭证」标记，防止被当收款凭证拿走
- 小票金额永远来自单据快照字段（`price/amount/total_amount`），不在前端重算，避免与账不平
