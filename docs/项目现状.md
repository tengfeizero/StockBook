## 3. 关键设计决策（改了会牵一发动全身）

1. **库存两层账**：`inventory`（商品×仓库：数量 + 均价）+ `location_inventories`（商品×仓库×库位：仅数量）。**成本永不按库位拆**。`location_id=0` 恒表示「未分配」，是合法值。
2. **成本方式按商品**：`fifo` / `weighted_avg`。批次商品必须 fifo，否则出库不扣批次（演示数据踩过）。
3. **单据状态机**：`draft → confirmed → voided`，只有 confirmed 影响库存与账；作废走反向流水，不物理删。
4. **多租户是"隐式隔离"**：全表带 `tenant_id`，GORM `TenantPlugin` 自动注入/过滤；0 号租户 = 单机版也参与隔离。因此 **service 方法必须带 ctx 并用 `s.db(ctx)`**。`tenants`/`plans` 是平台级表，不带 tenant_id。
5. **设置按租户存 `tenant_settings`**（主键 `tenant_id + key`）。旧的 `settings` 表已废弃为 `settings_legacy_v019`，不要再往里写。
6. **JWT 携带 `tenant_id`**，`JWTAuth` 校验用户归属，`TenantGuard` 管停用/到期（到期禁写可读），`LicenseGuard` 对 tenant>0 放行。
7. **授权**：Ed25519 签名 license.key + 机器码绑定 + 30 天试用；错误码 5001 过期后只读。
8. **演示数据是注册表**：`demo_profiles.go` 只放数据，`demo.go` 放流程，新增行业 = 加一份数据 + 注册。四套模板：`hardware` / `convenience` / `fresh` / `wholesale`。为保证可复现，随机数用固定 Seed。
9. **打印模板是设置项**：`print_logo`（data URL，前端 canvas 压到 240px）+ 7 个显隐开关（小票 `ticket_show_price/amount/partner/batch`，A4 `a4_show_price/amount/signs`），默认 true；关金额即送货单。
10. **前端产物与二进制强绑定**：`webdist` 只有 `.gitkeep` 入库，`build.sh` 构建后才拷入。`main.go` 检测不到 `index.html` 时只提供 API + 根路径指引页（保证 fresh clone 能编译能跑）。

## 4. 已知的坑（都会伪装成"莫名其妙的 bug"）

| 现象 | 真因 |
|---|---|
| 改了前端页面，刷新还是旧的 | `go:embed` 是编译期嵌入，必须重新 `go build` |
| 多租户下数据串了/看不见 | service 没用 `s.db(ctx)`，绕过了租户插件 |
| 批量插入 panic（reflect/slice） | 租户插件处理不了 slice，必须逐元素 Create |
| 明明删了 `uniqueIndex`，索引又回来了 | AutoMigrate 会按 tag 重建；唯一索引要在迁移里手动建复合的 |
| 盘点两行差异互相抵消 | 快照+调账被写进了明细循环（v0.18 修过，整单只做一次） |
| 演示数据重置卡在 2005 半路 | 货架近满容，重置前必须先关 `location_block_overflow` |
| curl 访问本地端口 502 / 返回乱码 | 本机有 `http_proxy`，加 `--noproxy '*'`；git-bash 下中文也可能 GBK 乱码（用 python urllib 更稳） |
| 后台起的服务莫名退出 | shell 的 `&` 会随会话回收，长跑进程要用后台任务方式启动 |
| 设置保存了但不生效 | 写进了旧 `settings` 表，实际读的是 `tenant_settings` |
| 换台机器 clone 后 `gofmt -l` 报**所有**文件未格式化 | Windows 的 `core.autocrlf=true` 把 `.go` 检出成 CRLF。`.gitattributes` 已强制 `*.go text eol=lf`；老工作区可 `git config core.autocrlf false` 后重新检出 |
| `jxc.exe -install` 报「无法连接服务管理器」 | 没用管理员权限。装服务/卸服务/查服务都必须管理员 |

## 5. 数据与密钥（新机器必读）

| 东西 | 在哪 | 新机器怎么办 |
|---|---|---|
| 业务数据库 | `data/jxc.db`（**不入库**） | 首次启动自动建库建表，`admin / admin123`；需要样本数据就 `POST /api/v1/demo/init` |
| JWT 密钥 | `data/.jwt_secret`（自动生成，0600） | 不用管；多实例部署才需显式设 `JXC_JWT_SECRET` |
| 授权私钥 | **不在仓库**，只在项目所有者手上（密码管理器/环境变量） | 需要签授权时向所有者要，或用 `go run ./cmd/genkey` 生成新对（会导致所有人失效） |
| 本机演示授权 | `data/license.key`，所有者「演示商贸」，2027-11-05 到期，用当前公钥签发 | 拷贝该文件即可；或让它跑 30 天试用 |
| 前端依赖 | `web/node_modules`（不入库） | `cd web && npm ci`（有 lock 文件，别用 `npm install` 漂版本） |

```bash
git clone <repo> && cd JXC
bash scripts/verify.sh          # 确认基线是绿的（会自动 npm ci / go mod download）
cd server && go run ./cmd       # 后端 :8080
cd web && npm run dev           # 前端 :5173
# 浏览器打开 5173，登录后从「系统设置 → 演示数据」载入 wholesale 模板，把流程点一遍
```
